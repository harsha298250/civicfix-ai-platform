## 3. Officer Review Workspace (`ComplaintReviewPage.jsx`)

The officer review interface (`/officer/complaints/:complaintId`) was updated while strictly preserving the existing UI design, styling, color palette, and layout.

### 3.1 Live AI Triage Card (Section B)
- **Heuristic Match Score**: Replaced fake `98.4% Confidence` with honest backend `confidence` value, clearly labelled:  
  `Rule Match: XX.X%` and accompanied by an explicit explanatory disclaimer:
  > *"Rule-Based Heuristic Match Score: XX.X% match based on deterministic keyword and domain lexicon analysis (not a trained probabilistic black-box model)."*
- **Detected Category & Recommended Priority**: Displayed from `complaint.aiTriage.detectedCategory` and `complaint.aiTriage.recommendedPriority`.
- **Hazard Classification Banner**: Displays safety warnings (e.g. `P1 - High Traffic Risk (Bus Route)`) in a styled alert box when populated.
- **Triage Rationale**: Displays `complaint.aiTriage.explanation` generated by the backend deterministic engine.
- **Adjudication Badge**: Dynamically indicates decision state (`Pending Officer Review`, `Accepted by Officer`, `Overridden by Officer`, `AI Advice Dismissed`).
- **Graceful Null Handling**: When no AI record exists, the card displays a clean informative notice without crashing.

### 3.2 Officer Adjudication Controls
Interactive action buttons enabled for reviewing officers:
1. **Accept Recommendation**:
   - Submits `{ action: "ACCEPT", version: complaint.version }` to `POST /api/complaints/{id}/ai/adjudicate`.
   - Adopts recommended category and priority into official record, updates status to `UNDER_REVIEW`, and appends an immutable timeline audit note.
2. **Override Recommendation**:
   - Opens a modal with validated dropdowns for all municipal categories (`ROADS`, `WATER_SEWERAGE`, `STREET_LIGHT`, `GARBAGE`, `DRAINAGE`, `PUBLIC_TRANSPORT`, `PARKS`, `GENERAL_MAINTENANCE`) and priority levels (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`), plus an officer notes field.
   - Submits `{ action: "OVERRIDE", category, priority, notes, version: complaint.version }`.
3. **Dismiss AI Advice**:
   - Opens a dismissal modal prompting for an optional officer reason.
   - Submits `{ action: "DISMISS", notes, version: complaint.version }`.

### 3.3 Duplicate Detection & Candidate Screening (Section C)
- Automatically triggers `officerService.getDuplicateCandidates(complaint.backendId || complaint.id)` upon page load.
- Renders candidate cards with:
  - Candidate reference ID (`#CF-2026-XXXXX`) and defect title.
  - Distance indicator (`XXm away` calculated from spatial coordinates, or `Distance N/A` if coordinates missing).
  - Lexical similarity match score (`XX% Match`).
  - Spatial screening explanation generated by backend.
  - **"Link as Duplicate" button**: Opens a confirmation dialog and submits `{ parentComplaintId, reason, version }` to `POST /api/complaints/{id}/duplicates/link`.
- If no candidates detected: displays verified green badge confirming the complaint is direct-dispatch eligible without duplicates.

### 3.4 Concurrency & Conflict Protection (HTTP 409)
- If an adjudication or duplicate linking request encounters an HTTP 409 conflict (record updated concurrently by another user or background task):
  - The UI does **not** silently retry.
  - An prominent amber banner appears: *"Concurrent Update Conflict (HTTP 409): This complaint was updated by another officer or background process. Please reload to review the latest changes before submitting."*
  - A **"Reload Latest Ticket"** action button safely re-fetches the record from PostgreSQL.

### 3.5 Linked Duplicate Banner
- If a complaint has already been linked as a duplicate of a master ticket (`complaint.duplicateOf` is present):
  - A distinctive purple banner clearly states: *"This complaint is linked as a duplicate of Master Ticket #CF-2026-XXXXX (Title). Resolving the master ticket will resolve this issue."*
